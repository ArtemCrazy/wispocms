## До переключения

1. Получить точный домен заказчика и доступ к его DNS. Добавить его в `deploy/compose.customer.yaml`, nginx-конфигурацию и необходимые OAuth redirect URI; направить A-запись на `129.101.122.78`. Веб-адрес `cms.kpbox.ru` не переключать без отдельного решения о его будущем.
2. Получить внешнее хранилище резервных копий. Настроить независимый бэкап БД и медиа, проверить контрольные суммы и восстановление в отдельную БД/том. Одной копии на новом VDS недостаточно.
3. Проверить исходное окружение и отсутствие выполняющихся задач. Создать свежие согласованные архивы БД/медиа на старом сервере, перенести их и повторно восстановить на новом сервере. Снимок от 11:14 UTC — только тестовый: последующие изменения на старом сервере в него не попадут.
4. Проверить вход администратора, файлы, сохранённые источники/версии, создание новой версии на безопасном тестовом проекте, HTTPS, почту и OAuth-переадресации. Зафиксировать момент смены источника данных и не допускать одновременного редактирования двух копий.
5. Groq: из контейнера API запрос к `api.groq.com` получает HTTP 403 по IPv4; с хоста по IPv6 без ключа — HTTP 401. Это не подтверждает работоспособность расшифровки. Проверить авторизованный запрос и решить сетевой доступ до приёмки этой функции.
