## Согласованные правила и закрытые пересечения

1. **Доступ.** Контент-центр хранит общие материалы workspace. Сервер и сессия используют одну
   политику: администратор Wispo либо поддерживаемая роль редактирования с явным доступом ко
   всем сайтам этого пространства. Частичный, пустой или legacy-доступ закрыт; UI согласован с API.
   Это предотвращает чтение материалов чужого сайта через общий workspace.
2. **Публикация.** По подтверждению пользователя администратор и владелец сайта публикуют без
   отдельного согласующего. Их действие сохраняет точную новую ревизию, согласование и публикацию
   в журнале Романа в одной транзакции с изменением живой статьи и старой историей. При первом
   обращении прежний публичный снимок сохраняется как baseline. Незавершённый CMS-черновик
   блокирует операцию без потери данных. Перенос статьи между сайтами учитывает оба журнала.
   Сотрудники не могут прямо публиковать из контент-центра; обычный процесс согласования CMS сохранён.
3. **Назначения перед выкладкой.** В снимке базы две memberships с legacy-ролью `employee`.
   Миграция Романа не назначает `siteIds`; нужна подтверждённая матрица «пользователь → роль → сайты».
   Автоматического расширения прав не сделано. Это условие выкладки, а не блокер merge кода.

Новых миграций для адаптера нет. Формат записи изменяется только при будущих явных публикациях:
дополнительно создаются неизменяемые CMS-ревизии и события в уже существующих таблицах.
