## Блокеры выпуска: требуется общее решение

1. **Границы доступа контент-центра.** `ContentCenterService.access()` разрешает работу по любой
   workspace membership. У Романа доступ ограничен `siteIds` и определёнными ролями. Поэтому
   пользователь одного сайта через прямой API контент-центра потенциально получает материалы
   всего пространства. Нужны единая серверная политика и соответствующий UI; нельзя просто
   присвоить всем доступ ко всем сайтам или считать скрытую кнопку защитой.
2. **Единый процесс публикации.** `CreationPublicationService.publish()/unpublish()` напрямую
   меняют `ArticleEntity` и старую историю. Они не используют `CmsRevisionsService`, конкретный
   approved revision ID и указатели новой истории. Выпуск в таком виде оставляет путь обхода
   согласования и рассинхронизации двух механизмов. Рекомендация: генерировать черновик и
   публиковать через общий процесс Романа; точные права контент-центра согласовать отдельно.
3. **Существующие сотрудники.** В снимке базы две memberships с legacy-ролью `employee`.
   Миграция Романа намеренно не назначает `siteIds`; после перехода их сессии не увидят сайты.
   Нужна подтверждённая матрица «пользователь → роль → сайты» и явное назначение, без догадок.

Эти пункты не исправлены самовольным изменением продуктовых правил. Draft PR и интеграционная
ветка служат безопасной точкой продолжения, не разрешением выпуска. До закрытия блокеров
не сливать в release/main и не запускать объединённый API на рабочей БД.
