# Подготовка информации: материалы и экран

Основание: [ТЗ «Подготовка информации»](https://wispo-agency.notion.site/3d89523e994e80b3bb10c584f707994e), проверено 19.09.2026. Прототип используется как ориентир компоновки, не как самостоятельный функциональный контракт.

## Реализованный сценарий

- Раздел внутри workspace, с сохранением общего меню CMS и шириной рабочей области.
- Последовательные блоки: ссылки, файлы, текстовые сведения, инструкция, процесс/последние версии, переход к документу.
- Категории ссылок: сайты, социальные сети, карты/отзывы, маркетплейсы, рекламные площадки, другие источники. Читается одна публичная HTTPS-страница, без авторизации и обхода защиты. Если чтение невозможно, сохраняется только ссылка с явным предупреждением; её содержимое не выдумывается.
- Настоящая загрузка PDF/DOCX/XLSX/PPTX/PNG/JPG/TXT/MD/CSV. Приватные оригиналы в PostgreSQL; доступны через авторизованный endpoint текущего workspace, только attachment/no-store/nosniff. Не попадают в публичную медиатеку сайта.
- Технические ограничения MVP: 10 МБ на файл, до 50 материалов. Лимит 40 000 символов для текста снят: длинные материалы сохраняются и обрабатываются существующим поэтапным механизмом. Общий лимит 50 МБ на workspace и его счётчик сняты по запросу заказчика 20.09.2026. Проверка текстовой кодировки и пределы отдельных AI-запросов сохранены.
- Таблица: имя, расширение, размер, дата, скачивание и удаление с подтверждением. Старые TXT/MD доступны для скачивания из сохранённого текста.
- Инструкция, явный режим без материалов, библиотека промптов, браузерная диктовка с отдельным согласием, сохранение черновика и защита от конкурентных изменений.
- Фактический статус запуска и этапы, история версий, отдельный документ для чтения и восстановление исторической версии в новую.
- Текст и оригиналы фиксируются в контексте запуска. Удаление источников не меняет начатую обработку и сохранённые результаты. Временный контекст очищается после завершения/ошибки; постоянного манифеста источников в версии нет.

## Границы этапа

- AI API намеренно не подключён. Генерация и распознавание документов/изображений не имитируются. TXT/MD/CSV читаются локально, остальные форматы сохраняются как оригиналы.
- Будущий провайдер реализует `PreparationProvider`, явно объявляет `supportsFiles: true` для обработки бинарных вложений и принимает `context.files`. Без этой способности запуск с бинарными файлами отклоняется, файлы не игнорируются молча. Не логировать содержимое материалов и вложений.
- Проверка сигнатур и расширений не является антивирусной проверкой. Оригиналы не исполняются, не распаковываются и не отображаются inline.
- «Создать форму», форматы экспорта и внешние интеграции отложены самим ТЗ; фиктивных действий для них нет.
- Проценты прогресса, время окончания и внутренние этапы модели не выдумываются; пока отображаются только состояния, подтверждённые сервером.

## Проверки

Изолированный PostgreSQL: HTTP multipart/attachment, ограничения размера, ACL workspace, безопасная выдача метаданных, квоты при параллельных загрузках, неизменность контекста после удаления, запрет тихого игнорирования вложений, прежние проверки версий/блокировок. Web: SSR коллекции материалов и предупреждений, проверки диктовки/этапов. После релиза — проверка экрана во встроенном Browser.

Миграция аддитивная. Перед применением — свежая резервная копия БД; она включает приватные оригиналы. При откате приложения новые колонки сохранять, не выполнять down с удалением файлов.
