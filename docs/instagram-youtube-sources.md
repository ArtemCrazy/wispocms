# Instagram и YouTube: сбор источников

Область: собственные материалы заказчика. Настройка приложения не означает,
что доступ уже проверен. Сбор использует существующую очередь и не запускает AI;
сохранение одной ссылки также не запускает сеть. Итоговые версии неизменяемы.

## YouTube

1. Администратор создаёт проект Google Cloud, включает YouTube Data API v3,
   выпускает API key и ограничивает его этим API и IP сервера CMS.
2. В «Настройках платформы → YouTube» сохраняет ключ; он шифруется серверным
   `AI_ENCRYPTION_KEY` и не возвращается браузеру/AI.
3. Сотрудник добавляет социальный источник YouTube: `youtube.com/@handle`,
   `/channel/UC…` или старый `/user/name`. `/c/…` и одиночные видео не поддерживаются.
4. В информации об источнике нажимает «Обновить сбор». Только реальный успешный
   сбор подтверждает работу ключа и квоты. Пользовательский Google-вход не нужен.

Читаются описание канала, названия, описания, даты и ссылки до 100 последних
публичных видео из uploads playlist. Возраст не ограничивается; не больше пяти
страниц списка/90 секунд и 700 тысяч символов за источник. Удалённые, приватные
или чужие видео помечаются недоступными. При достижении лимита есть предупреждение.
Видео, аудио, субтитры, комментарии и публикации сообщества не читаются.
Не представлять описание видео как просмотр самого ролика.

Документация: [channels.list](https://developers.google.com/youtube/v3/docs/channels/list),
[uploads playlist](https://developers.google.com/youtube/v3/guides/implementation/channels),
[captions.download — отдельная авторизация](https://developers.google.com/youtube/v3/docs/captions/download).

## Instagram

1. Создать приложение Meta с **Instagram API with Instagram Login**.
   Использовать Instagram App ID/Secret, не подменять их ключом VK или Facebook
   Page access token. Нужен профессиональный профиль Business/Creator.
2. Настроить минимальное разрешение `instagram_business_basic`. Для тестов
   аккаунт должен иметь соответствующую тестовую роль в приложении. Для внешних
   клиентских аккаунтов заранее оформить необходимое одобрение доступа у Meta;
   сам факт создания приложения не означает готовность для всех заказчиков.
3. Зарегистрировать точный доверенный URI:
   `https://cms.kpbox.ru/api/social/instagram/callback`.
   Домен должен быть в серверном `WEB_ORIGIN`. При смене домена URI меняется
   и в Meta, и в CMS; временный `kpbox.ru` требует последующего переноса.
4. Администратор в «Настройках платформы → Instagram» вводит App ID, URI и Secret.
   После изменения настроек прежние аккаунты нужно подключить заново.
5. Открыть CMS именно на домене callback, войти в рабочее пространство,
   добавить `instagram.com/profile`, затем нажать «Подключить Instagram».
   Владелец входит на стороне Instagram и разрешает чтение; пароль CMS не получает.
6. Вернувшись, открыть информацию об источнике и нажать «Обновить сбор».

На обратном переходе требуется та же авторизованная CMS-сессия. Состояние OAuth
одноразовое, живёт 10 минут и связано с пользователем, workspace, материалом,
его ревизией и версией приложения; в БД хранится только хеш состояния.
Выбранный Instagram username должен совпадать с источником. Повторное использование,
смена ссылки/приложения, истечение срока или чужой пользователь отклоняются.
Подключение/отключение не меняется во время обработки рабочего пространства.

Читаются идентификатор профиля, подписи к первым 100 публикациям API, даты и
постоянные ссылки. Посты без подписи исключаются с причиной. Нет OCR, распознавания
речи, чтения Stories, комментариев или переписки; текст Reels — только подпись.
Условия: до пяти страниц списка, 90 секунд, 700 тысяч символов. Пагинация строится
по курсору на фиксированном API-хосте; произвольный `paging.next` не открывается.

Токен обменивается сервером на долгосрочный и хранится AES-256-GCM с привязкой
к workspace/источнику. Если до истечения остаётся меньше семи дней, во время сбора
предпринимается обновление ещё действующего токена. Это не фоновое расписание:
после длительного перерыва или отзыва доступа потребуется новое подключение.
Отсоединение удаляет локальный токен и текущий снимок, но не исторические версии.
Разрешение приложения при необходимости также отзывается в настройках Instagram.

Документация: [официальная коллекция Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api),
[Instagram Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login).
Используется Graph API `v23.0`; поддержку версии проверять перед её обновлением.

## БД, безопасность и восстановление

Аддитивная миграция `1791091200000-InstagramYoutubeSources.ts`:

- `platform_social_settings`: общий ключ YouTube / настройки приложения Instagram;
- `cc_instagram_connections`: привязки аккаунтов и зашифрованные токены;
- `cc_instagram_oauth_states`: краткоживущие одноразовые состояния авторизации.

Прежние строки не переписываются; в таблице настроек создаются две пустые записи.
Уже существующие JSON-снимки `cc_materials.site_pages` и очередь используются
для новых сетей. Смена ссылки очищает её Instagram-привязку и незавершённые OAuth
состояния. Удаление материала удаляет их каскадно. Недоступный API не заменяет
сохранённый снимок при явном обновлении. Конфликт ревизии не перезаписывает материал.

Ключи/токены/коды и ответы ошибок провайдеров не логировать, не передавать AI.
Обязательная nginx-настройка для обоих доменов: OAuth callback обслуживается
отдельным location с `access_log off` и `error_log /dev/null crit`, чтобы даже
ошибка upstream не записывала URI с кодом авторизации. Применить вместе с кодом и проверить
`nginx -t`. При другом ingress также отключить/редактировать query-параметры
callback в журналах. Ответ callback имеет `no-store` и `no-referrer`.

Автоматический разрушительный `down` запрещён. Откат приложения оставляет
аддитивные таблицы/секреты; старый код не поддерживает новые социальные источники,
поэтому их сбор на старой версии не запускать. Перед рабочей миграцией — свежий
проверенный дамп и сверка параллельной ветки/серверных миграций.

Настоящая авторизация Meta и настоящий ответ YouTube не заменяются моками.
До настройки приложений допустимы только проверки кода, изолированной БД и UI
с честным состоянием «Не настроено»; не объявлять живой сбор подтверждённым.
