# DeepSeek: настройки и запуск

Администратор платформы: меню рабочего пространства → **Настройки** → **DeepSeek**.
Прямая ссылка: `/?view=platform-settings`.

1. Вставить ключ, выбрать модель, сохранить. Ключ после сохранения не возвращается клиенту.
2. Нажать «Проверить подключение». Проверяется `/models`: авторизация и доступность выбранной модели, без генерации и отправки материалов. Это не проверка баланса или успешности будущей генерации.
3. В нужном workspace создать текстовый материал, запустить подготовку информации. После получения версии выбрать площадку и кластер в «Создании контента», запустить генерацию. Проверить результат, корректировку, принятие предложений и публикацию отдельно. Генерация использует платный аккаунт DeepSeek; сохранение ключа ничего не запускает.

## Границы первого подключения

Подключены подготовка текстовой информации, генерация статей и предложения корректировки. JSON проходит существующую доменную валидацию; обрезанный/пустой ответ не сохраняется как результат. Нет автоматических повторов оплачиваемых запросов и автоматической публикации.

PDF/Office/изображения и дополнительные вложения генерации пока **не поддерживаются** (`supportsFiles=false`), запрос с ними отклоняется до отправки. Текст из TXT/MD/CSV используется существующим механизмом материалов. URL не загружаются: адрес без текста не равен прочитанному источнику. Поисковый провайдер исследования не подключён; текстовую модель не выдаём за поисковик.

## Хранение и эксплуатация

- Общий ключ платформы, администратор может заменить/удалить его; сотрудники не имеют доступа к API настроек. Контекст формируется существующими workspace-процессами, данные соседних workspace не добавляются.
- В БД `platform_ai_settings` только AES-256-GCM ciphertext, модель, ревизия, автор/время изменения и время успешной проверки. Audit исключает `apiKey`, `api_key`, `encryptedKey` и прочие секреты.
- `AI_ENCRYPTION_KEY` — отдельный случайный 32-байтовый ключ в hex (64 символа) в приватном серверном `deploy/.env.preview`. Не брать из JWT_SECRET, не коммитить, не печатать в логах. Compose передаёт его только API, не web. Если отсутствует, ввод ключа отключён.
- Сохранить резервную копию мастер-ключа в защищённом хранилище администратора отдельно от дампа БД. Потеря или замена мастер-ключа делает ранее сохранённый API-ключ нечитаемым; потребуется восстановление мастер-ключа либо повторный ввод API-ключа. Не менять мастер-ключ при обычных релизах.
- Изменения защищены optimistic revision: второй администратор не перезаписывает сохранённые настройки незаметно. Проверка старого ключа не подтверждает новый после замены. Статус конфигурации держится в памяти единственного API-инстанса; при масштабировании на несколько инстансов добавить общую инвалидацию статуса (сами credentials перечитываются из БД перед каждым запросом).
- Удаление ключа блокирует новые запросы, но не отзывает уже отправленные; для немедленного отзыва отозвать ключ в кабинете DeepSeek.
- DeepSeek получает запросы только на фиксированный `https://api.deepseek.com`, редиректы запрещены. Нет произвольного URL провайдера, SDK, логирования тел ответов/промптов/ключей, автоматических ретраев.

Сверено с официальными API: https://api-docs.deepseek.com/api/create-chat-completion/ и https://api-docs.deepseek.com/guides/json_mode/ (19.09.2026). Модели `deepseek-flash` и `deepseek-v4-pro`, thinking выключен, JSON output, до 8192 токенов ответа. Это ограничение первого адаптера, не обещание максимума платформы DeepSeek.

Реальный end-to-end проводится после ввода пользовательского ключа. Тесты с подменённым транспортом не заменяют его.
