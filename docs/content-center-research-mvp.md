# Исследование и анализ: границы первого этапа

Источник: https://wispo-agency.notion.site/3d89523e994e80a687ffc0239062cc82. Прочитан полностью 19.09.2026; последняя правка страницы 11.09.2026.

## Реализуем сейчас

1. Вкладки исследований: конкурентный анализ, JTBD, анализ спроса, SEO-анализ. Для трёх последних нет описанной логики — только явный статус проектирования.
2. Конкурентный анализ: Данные → Поиск источников → Результат. Сохраняется CMS-shell и ширина рабочей области.
3. Выбор структурированных выводов (по умолчанию) или полного результата, просмотр доступного документа прямо здесь. Сырые материалы не передаются. Без обработанных данных можно работать, указав направление исследования.
4. Категории поиска, собственные категории, ручные ссылки, включение/исключение, изменение категории. Изменения сохраняются в workspace с защитой от перезаписи другим сотрудником.
5. Серверный контракт автоматического поиска без подключения поставщика AI. Никаких выдуманных результатов или имитации запуска. Провайдер подключается отдельно.
6. Подтверждение списка фиксирует неизменяемую копию выбранных источников, их категорий и контекста. Изменение черновика не переписывает ранее подтверждённые списки.

## Стык требований и отложенная логика

ТЗ подготовки информации описывает единый документ, а этот документ упоминает отдельные структурированные выводы. Они сейчас не формируются. Не подменяем их полным текстом, не создаём автоматическое резюме без согласованной логики. Вариант выводов показывается как недоступный; полный результат доступен при наличии сохранённой версии. В отсутствие любых результатов переход дальше разрешён.

«Результат» в самом ТЗ помечен «Обсуждаем с Даней». Сейчас здесь показываем только факт и состав подтверждения списка; генерацию самого анализа, чат, версии выводов, экспорт и публикацию не проектируем самостоятельно.

## Риски и проверки

Tier 2: новые workspace-данные, миграция и внешний контракт. Все API проверяют ACL; чужие IDs и версии недоступны. Оптимистичная ревизия защищает коллективную работу; подтверждение сверяет также версию подготовки информации. Ограничения MVP: 20 категорий, 100 источников, направление до 8000 символов; публичные HTTPS-ссылки без учётных данных. Это ограничения реализации, не новые бизнес-требования.

Основной сценарий: без обработанных данных → направление → своя категория и ручной источник → сохранить → перезагрузить → исключить источник → подтвердить только выбранные → изменить черновик → ранее подтверждённый список остаётся прежним. Дополнительно: ACL и конкурентные правки, отсутствие сырых материалов в контексте, отключённый AI без фальшивого результата. Проверка на общем сайте во встроенном Browser после выпуска; main не трогаем.

## Контракт подключения поиска

Зарегистрировать `ResearchSearchProvider` под токеном `RESEARCH_SEARCH_PROVIDER`. Вход: направление, выбранные категории и только подготовленный документ (либо null при отсутствии материалов). Ответ: проверенные реальные источники с названием, публичным HTTPS-адресом, ID выбранной категории и кратким описанием. Выдуманные моделью URL не являются поиском. Источники и документы — недоверенные данные, не системные инструкции. Ключи и запросы провайдера остаются на сервере.

Ограничение вызова — 45 секунд; адаптер обязан поддерживать AbortSignal. Блокировка в БД защищает от параллельных запусков и истекает после аварийного обрыва. Автоматического повтора платного вызова нет. Ошибка не меняет список. Результат не перезаписывает изменения другого сотрудника или новую версию подготовленных данных. Отдельные очереди исследования, диалоги и генерация отчёта до проектирования «Результата» не добавляются.
